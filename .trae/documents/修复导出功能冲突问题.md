# 问题分析

通过分析代码和用户提供的详细问题描述，我发现了导致导出功能异常的根本原因：

1. **容器变量名冲突**：两个导出函数（`exportAsImage` 和 `exportAsPDF`）都使用了相同的变量名 `exportContainer`
2. **消息键冲突**：两个导出函数都使用了相同的消息键 `key: 'export'`
3. **DOM操作时序问题**：连续导出时，可能存在容器创建和删除的时序问题

这些问题会导致：
- 后执行的导出函数覆盖先执行的导出函数的容器或消息
- 连续导出同一类型时，第二次导出可能使用了已被删除的容器引用

# 解决方案

我将修改两个导出函数，解决这些冲突问题，同时保持其他代码框架不变：

1. **修改图片导出函数**：
   - 将容器变量名从 `exportContainer` 改为 `imageExportContainer`
   - 将消息键从 `key: 'export'` 改为 `key: 'export-image'`

2. **修改PDF导出函数**：
   - 将容器变量名从 `exportContainer` 改为 `pdfExportContainer`
   - 将消息键从 `key: 'export'` 改为 `key: 'export-pdf'`

3. **优化容器创建和删除逻辑**：
   - 确保每个导出函数都使用完全独立的容器
   - 确保容器在使用后被正确删除

4. **保持其他代码不变**：
   - 保留导出时使用新容器的做法
   - 保留所有样式处理逻辑
   - 保留地图截图处理逻辑

# 预期效果

修改后，两个导出函数将使用独立的容器和消息键，不会相互干扰。无论是先导出PDF后导出图片，先导出图片后导出PDF，还是连续导出同一类型，都能成功导出完整的行程计划，不会出现空白的情况。
